Under the hood / My contribution+

Widget lifecycle

A game-instance-managed stack pushes and pops widgets, giving menus a shared structure rather than isolated behaviours.

Input-aware navigation

Custom navigation supports mouse, keyboard, and gamepad, with icon switching for input types and PlayStation / Xbox controllers.

Menu behaviour

Main menu, settings, pop-ups, and button highlighting. Vertical navigation uses Blueprint arrays; horizontal navigation uses C++ function-pointer maps.

Under the hood+

Four stacks. Clear input priority.

Frontend → GameHUD → GameMenu → Modal. Each stack tracks where the player came from, with modal widgets taking the highest input priority.

Widgets on demand

Gameplay Tags identify soft widget references. Async actions ask the frontend subsystem to load the widget and push it onto the appropriate stack.

Settings as data

Settings are split into config storage, an options registry, data objects, and visual entry widgets. The frontend also connects to the level loading system.

SimpleTelem

Turn playtests into something you can inspect. A Blackboard-based telemetry plugin for tracking player data, visualising movement, and exporting results.

BlackboardHeatmappingData export
Watch walkthrough ↗Explore source ↗
Under the hood+

Designed for iteration

Designers add tracked variables through the Unreal Blackboard interface without changing code. Tracked values keep their original types so the data can also be reused during gameplay.

See where players spend time

Two actor components support data tracking and heatmapping. Sampling intervals are configurable, and heatmap cubes change colour based on how long a player stays in a position.

Take the data further

Export Blackboard data to a spreadsheet for closer examination. Watch the setup guide ↗
